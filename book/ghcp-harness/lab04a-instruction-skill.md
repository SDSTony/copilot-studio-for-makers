# 모듈 5-1. Instructions 기반 사전 검토 Skill 만들기

## 학습 목표

- 전체 Instructions와 요청별 Skill의 차이를 이해합니다.
- 출장 정보 확인, 비용 계산, 규정 검토를 수행하는 Skill을 만듭니다.
- 정상 입력, 정보 부족, 잘못된 입력의 동작을 비교합니다.
- Skill 추가 전·후에 같은 프롬프트를 사용하여 응답과 수행 절차의 차이를 확인합니다.

## 사전 준비

[모듈 4](lab03-onedrive-knowledge.md)의 OneDrive 지식 소스가 사용 가능한 상태여야 합니다. 이 모듈에서는 등록 Tool이나 Workflow를 만들지 않습니다.

## 1. Skill 없이 Preview에서 먼저 테스트하기

모듈 3에서 작성한 전역 Instructions와 모듈 4에서 연결한 OneDrive Knowledge는 그대로 유지합니다. 아직 `trip-precheck` Skill은 추가하지 않습니다. 파일 생성 Skill, 등록 Tool, 메일 MCP, Workflow도 연결하지 않은 상태에서 진행합니다.

1. **Build → Skills**에서 `trip-precheck`가 아직 없는지 확인합니다.
2. **Preview**를 열고 아래 A·B·C를 각각 **새 대화**에서 입력합니다.
3. 응답을 복사하거나 화면을 캡처하여 **5절 비교표의 추가 전 실제 관찰**에 기록합니다. 계산식, 빠진 정보 질문, 응답 순서와 근거 표시를 살펴봅니다.
4. 모델, Instructions, Knowledge와 나머지 연결 상태를 기록하고 이후 비교가 끝날 때까지 바꾸지 않습니다.

### 테스트 A. 정상 입력

```text
2026-11-10부터 2026-11-12까지 부산에 혼자 고객사 방문 출장을 갑니다.
교통은 KTX 일반석 왕복 120000원, 숙박은 세금 포함 1박당 150000원으로 2박,
기타 비용은 없습니다. 예상 경비와 교육용 규정 준수 여부를 사전 검토해 주세요.
```

**관찰할 점:** 숙박 합계·예상 총액·한도 초과액을 구분하는지, 계산식과 근거를 보여주는지, 사전 검토를 승인처럼 표현하지 않는지 확인합니다.

### 테스트 B. 정보 부족

```text
부산에 2박 3일 출장을 가요. 숙박비는 1박당 120000원입니다.
전체 경비를 계산해 주세요.
```

**관찰할 점:** 날짜·목적·교통비·기타 비용 등 빠진 항목만 묻는지, 이미 제공된 정보를 다시 묻거나 없는 비용을 0원으로 가정하는지 확인합니다.

### 테스트 C. 잘못된 입력

```text
2026-11-12부터 2026-11-10까지 부산 출장입니다.
교통비는 -10000원이고 숙박은 2.5박이에요. 그대로 검토해 주세요.
```

**관찰할 점:** 날짜 순서·음수 금액·소수 숙박일 수의 오류를 짚는지, 잘못된 값으로 계산을 진행하는지 확인합니다.

```{note}
Skill이 없어도 기존 Instructions와 Knowledge, 모델의 기본 능력으로 올바르게 답할 수 있습니다. 반드시 추가 전에는 실패하고 추가 후에는 성공해야 하는 실습이 아닙니다. 실제 응답과 실행 정보를 비교하여, Skill이 검토 절차와 출력 항목을 얼마나 일관되게 적용하게 하는지 살펴봅니다.
```

## 2. Skill 생성

1. **Build → Skills → Add skill**을 엽니다.
2. **Create from blank**를 선택합니다.
3. 이름과 설명을 아래와 같이 입력합니다.

| 항목 | 값 |
|---|---|
| Name | `trip-precheck` |
| Description | 국내 1인 출장의 일정·비용을 사전 검토하거나 준비 체크리스트를 요청할 때 사용한다. 정보를 확인하고 Knowledge에 근거해 숙박 한도와 예상 경비를 검토한다. 목록 등록·이메일 발송·승인·예약은 수행하지 않는다. |

## 3. Skill Instructions 작성

다음 내용을 Skill의 **Instructions**에 넣고 **Create / Save**합니다.

```text
# 국내 출장 사전 검토

## 정보 확인
1. 국내 1인 출장인지 확인한다. 해외 또는 다인 출장은 지원 범위를 안내한다.
2. 목적지, YYYY-MM-DD 시작일·종료일, 출장 목적, 전체 왕복 교통비,
   세금 포함 1박당 숙박비, 숙박일 수, 전체 기타 비용을 확인한다.
3. 사용자가 이미 말한 정보는 다시 묻지 않는다.
   빠진 항목만 질문한다. 기타 비용이 없다는 확인을 받아야 0원으로 기록한다.
4. 원 단위 정수가 아닌 금액이나 음수 금액, 존재하지 않는 날짜, 시작일보다 빠른 종료일,
   정수가 아닌 숙박일 수를 발견하면 수정 요청한다.
5. 교육용 정책에 따라 숙박일 수와 시작일·종료일 날짜 차이가 맞는지 확인한다.
   당일 출장은 숙박일 수와 숙박비가 모두 0이다. 불일치는 추측하지 않고 확인한다.

## 근거 조회와 계산
6. 연결된 출장 규정과 경비 기준을 읽어 적용 범위와 숙박 한도를 확인한다.
   문서를 읽지 못하면 규정 검토를 완료했다고 말하지 않는다.
7. 숙박 합계 = 1박당 숙박비 × 숙박일 수.
   예상 총액 = 교통비 + 숙박 합계 + 기타 비용.
   숙박 한도 초과 총액 = max(1박당 숙박비 - 문서의 1박 한도, 0) × 숙박일 수.
8. 모든 금액을 KRW로 표시한다. 입력이 빠졌으면 확정 합계를 내지 않는다.
9. 한도 이내/초과는 숙박 기준의 판단이다.
   교통 수단이 확인되지 않았으면 확인 필요로 적고,
   기타 비용이 있으면 용도를 묻고 규정 판단을 별도 확인으로 표시한다.
   식비나 해외 한도를 만들지 않는다.
   이후 등록에 전달할 ReviewResult는 기타 비용이 0일 때
   "한도 이내" 또는 "한도 초과"로 정리한다.
   기타 비용이 양수이면 숙박 한도 이내는 "별도 확인",
   숙박 한도 초과는 "한도 초과 / 별도 확인"으로 정리한다.
   응답에서는 이 요약값과 별개로 숙박 판정과 기타 비용의 확인 필요성을 각각 설명한다.

## 응답
10. 다음 순서로 답한다.
    - 확인된 출장 정보와 미확인 정보
    - 비용 내역과 계산식
    - 숙박 검토 결과와 한도 초과 총액
    - 별도 확인 사항
    - 출장 준비 체크리스트
    - 근거 문서 이름과 관련 절
11. 결과는 사전 검토이지 승인·예약·정산이 아님을 안내한다.
12. 이 Skill에서는 파일 생성, Excel 등록, 이메일 발송을 수행하지 않는다.
```

```{note}
Skill의 Description은 언제 활성화할지, Instructions는 활성화 후 어떻게 수행할지를 설명합니다. 전역 Instructions에 모든 절차를 중복해서 넣기보다 역할과 경계를 남기고 특정 절차는 Skill로 분리합니다.
```

## 4. Skill 추가 후 같은 프롬프트로 다시 테스트하기

1. Skill이 저장되어 에이전트에 추가되었는지 확인합니다.
2. Instructions, Knowledge, 모델과 나머지 연결은 바꾸지 않습니다. 두 시험 사이의 변경은 `trip-precheck` Skill 추가뿐입니다.
3. **1절의 테스트 A·B·C를 글자 그대로 다시 입력**합니다. 이전 대화를 이어가지 말고 이번에도 질문마다 **새 대화**를 시작합니다.
4. 실제 응답과 아래 기대 결과를 대조하고 **5절 비교표의 추가 후 실제 관찰**을 작성합니다.

### 테스트 A의 기대 결과

| 확인 항목 | 기대 결과 |
|---|---|
| 숙박 합계 | 150,000 × 2 = 300,000원 |
| 예상 총액 | 120,000 + 300,000 + 0 = 420,000원 |
| 숙박 허용 총액 | 130,000 × 2 = 260,000원 |
| 숙박 한도 초과 총액 | (150,000 − 130,000) × 2 = 40,000원 |
| 검토 결과 | 숙박 한도 초과, 별도 검토 필요. 승인 완료가 아님 |
| 부작용 | 파일 생성·등록·이메일 발송 없음 |

Activity trace에서 Skill 활성화와 지식 활용 정보를 확인합니다. 답변에 Skill 이름을 언급했다는 이유만으로 사용한 것으로 판단하지 않습니다. 실행 정보에서 활성화 여부를 확인할 수 없다면 **활성화 확인 불가**로 기록합니다.

### 테스트 B의 기대 결과

날짜, 목적, 교통비, 기타 비용 등 빠진 정보만 확인하고 총액을 확정하지 않습니다.

### 테스트 C의 기대 결과

날짜 순서, 음수 금액, 숙박일 수를 수정하도록 요청합니다. 계산 완료 또는 등록 완료로 답하지 않습니다.

## 5. 추가 전·후 차이 비교하기

| 비교 항목 | 추가 후 확인할 기준 | 추가 전 실제 관찰 | 추가 후 실제 관찰 |
|---|---|---|---|
| A. 비용 계산 | 숙박 300,000원, 총액 420,000원, 숙박 초과 40,000원을 계산식과 함께 구분 | 직접 기록 | 직접 기록 |
| A. 검토 절차와 출력 | 확인 정보 → 비용 계산 → 숙박 검토 → 별도 확인 → 체크리스트 → 근거 순서로 안내 | 직접 기록 | 직접 기록 |
| B. 정보 부족 | 빠진 항목만 질문하고 확정 총액은 내지 않음 | 직접 기록 | 직접 기록 |
| C. 입력 오류 | 잘못된 날짜·음수 금액·소수 숙박일 수의 수정 요청 | 직접 기록 | 직접 기록 |
| 근거와 실행 경계 | Knowledge 근거를 표시하고 승인·파일 생성·등록·메일 발송으로 확대하지 않음 | 직접 기록 | 직접 기록 |
| Skill 활성화 | 응답의 자기 설명이 아닌 실행 정보로 확인 | Skill 미추가 | 확인 결과 또는 확인 불가 기록 |

**함께 이야기하기**

- Skill 추가 후 새로 보이거나 더 일정해진 검토 단계는 무엇인가요?
- 기존 Instructions만으로도 잘했던 부분은 무엇인가요?
- 변화가 관찰된 항목은 Skill Instructions의 어떤 규칙과 연결되나요?
- 차이가 작다면 Skill 활성화 여부를 확인했나요? 확인할 수 없다면 그 한계도 기록했나요?

Skill은 모델이 전혀 못 하던 일을 무조건 가능하게 하는 장치라기보다, 특정 요청에 사용할 수행 절차를 분리해 재사용하는 방법입니다. 한 번의 비교로 품질 향상이 보장된다고 결론 내리지 않습니다. 기대와 다르면 Description과 관련 규칙을 점검한 뒤 같은 프롬프트로 새 대화에서 재시험합니다. 비교가 끝나면 Skill을 유지하고 다음 모듈로 진행합니다.

## 문제 해결

| 증상 | 조치 |
|---|---|
| 일반 규정 질문에도 긴 절차를 시작함 | Description을 "일정·비용 사전 검토 요청"으로 좁히고 새 대화에서 시험 |
| 한도가 지침의 값으로 고정됨 | 한도는 Knowledge에서 읽도록 하고 Skill에 실제 금액을 중복 하드코딩하지 않음 |
| 기타 비용을 0으로 추정함 | "없음 확인 후 0" 규칙을 검토하고 정보 부족 프롬프트 재시험 |
| 총액과 한도 초과액을 혼동함 | 계산식과 출력 항목을 구분하고 위 표의 숫자로 대조 |

## 완료 체크리스트

- [ ] `trip-precheck` Skill을 만들었습니다.
- [ ] Skill 추가 전에 A·B·C를 각각 새 대화로 시험하고 응답을 기록했습니다.
- [ ] 다른 설정은 유지하고 Skill 추가 후 같은 세 프롬프트로 재시험했습니다.
- [ ] 추가 전·후 차이와 Skill 활성화 확인 결과를 비교표에 기록했습니다.
- [ ] 정상 입력에서 총액 420,000원과 초과액 40,000원이 맞습니다.
- [ ] 정보 부족과 잘못된 입력을 확인합니다.
- [ ] 사전 검토와 실제 승인·등록을 구분합니다.
